
## Critic 蒸馏时应该学什么？

critic 不应该只学：

```text
progress / failure / done
```

它还应该学一个给 verifier 使用的短 summary：

```text
summary_to_history
```

所以 critic 的蒸馏目标最好是：

```json
{
  "outcome": "progress | failure | done | no_effect",
  "failure_type": "none | wrong_page | wrong_target | text_error | popup_blocking | premature_complete | no_effect",
  "suggested_recovery": "continue | navigate_back | clear_text | close_dialog | retry | complete_task",
  "summary_to_history": "The previous action opened the wrong folder. Avoid continuing there and go back to the file list."
}
```

其中最重要的是最后一个字段：

```text
summary_to_history
```

因为它会被写入下一步 history，让 verifier 看。

---

## 为什么 critic 要直接学习 summary？

因为你最终部署时是：

```text
before_ui + action + after_ui
↓
critic
↓
summary_to_history
↓
下一步 verifier
```

如果 critic 没学过 summary，只输出标签：

```json
{
  "outcome": "failure",
  "failure_type": "wrong_page"
}
```

那你还得额外写一个规则模板把标签转成 summary：

```text
The previous action failed because it led to the wrong page...
```

这样也可以，但会比较死板。

更好的方式是让 critic 同时输出：

```text
判断结果 + 可写入 history 的自然语言/半结构化反馈
```

这样 critic 就是一个真正的 **memory writer**。

---

## 但 summary 不要太自由

critic 的 summary 是给 verifier 用的，不是给人看的，所以不要写很长。建议固定模板。

例如：

```text
[Critic]
outcome: failure
reason: wrong_target
previous_action: click(index=12)
advice: avoid this action and navigate_back.
```

比下面这种更好：

```text
It seems that the last action might not have been useful because maybe the agent clicked an incorrect item, so it could consider trying something else.
```

太自由会导致 verifier 输入分布不稳定。

---

## 蒸馏数据应该长什么样？

critic 的一条训练样本应该是：

```json
{
  "input": {
    "goal": "Delete q2a8_fancy_banana.mp3 from Notifications folder.",
    "history": [
      "Opened Files.",
      "Clicked Downloads."
    ],
    "before_ui": "...",
    "action": "{\"action_type\":\"click\", \"index\":12}",
    "after_ui": "..."
  },
  "output": {
    "outcome": "failure",
    "failure_type": "wrong_folder",
    "suggested_recovery": "navigate_back",
    "summary_to_history": "[Critic] The previous action opened Downloads, but the target file is in Notifications. Avoid continuing in Downloads and navigate back."
  }
}
```

然后训练 critic 做：

```text
input -> output JSON
```

## Stage 3 和 Stage 4 的区别

 
“既然 critic 蒸馏时已经学 summary，那 Stage 3 用 critic 生成 summary 是不是重复？”

不重复，区别是：

### 蒸馏阶段

```text
让 C 学会怎么生成 summary
```

这是训练 critic。

### 批量生成阶段

```text
用训练好的 C 给大量轨迹自动补 summary
```

这是为了构造 verifier 的训练数据。

也就是说：

```text
Stage 3: train C to be a summary writer
Stage 4: use C as a summary writer
```

## 流程图



```text
Stage 0: V-Droid baseline
  - 复现原始 V-Droid
  - 记录失败类型、SR、latency

Stage 1: Raw trajectory collection
  - goal
  - history
  - before_ui
  - action_space
  - selected_action
  - after_ui
  - final success/failure

Stage 2: Critic-label annotation
  - teacher / 人工标注每个 transition
  - outcome
  - failure_type
  - suggested_recovery
  - summary_to_history

Stage 3: Critic distillation
  - 训练 C: before_ui + action + after_ui + goal + history -> critic JSON
  - C 学会判断 outcome，也学会写 summary

Stage 4: Critic-history generation
  - 用 C 给更多 raw trajectories 自动生成 summary_to_history
  - 把 summary append 到下一步 history

Stage 5: P3 data construction for verifier
  - chosen/rejected prompt 中包含 critic summary
  - 让 V 学会读 critic feedback

Stage 6: Verifier LoRA tuning
  - 微调 V-Droid verifier
  - 避免看到 failure 就总是 back

Stage 7: Joint inference
  - V 选动作
  - 执行
  - C 写 summary
  - 下一步 V 读 summary 再选动作
```

## 关键点：C 的 summary 要和 V 的训练输入一致

这非常重要。

如果 critic 蒸馏时输出的是：

```text
"The previous action failed because..."
```

但 verifier 微调时看到的是你手写模板：

```text
[Critic] outcome=failure; reason=wrong_page; recovery=back
```

那还是会有格式不一致。

所以最好一开始就固定：

```text
critic output format = verifier history format
```

例如统一用：

```text
[Critic Feedback]
outcome: failure
reason: wrong_page
previous_action: click(index=12)
advice: navigate_back
avoid: click(index=12)
```

那么：

```text
C 蒸馏时学这个格式
V 微调时读这个格式
联合推理时也用这个格式
```

这叫 **train-inference format alignment**。

---

## 意义

不是简单的：

```text
先蒸馏 critic，再微调 verifier
```

而是：

```text
先蒸馏一个能够生成 verifier-readable feedback 的 critic，
再用这种 feedback 构造 verifier 的 critic-augmented P3 数据，
最后微调 verifier 学会利用 critic feedback。
```

一句话：

> **critic 蒸馏时就要学习 summary，因为 critic 的核心角色不是只判断对错，而是把 post-action outcome 压缩成下一步 verifier 能读懂的 history memory。**
